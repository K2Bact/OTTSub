# 광고 전후 관찰 도구

**광고를 고치는 확장이 아니라, 실제 광고 감지·시간 설계에 필요한 기록을 수집하는 임시 도구다.** OTTSub 제품 manifest/src는 수정하지 않았다. 이 폴더만 별도 확장으로 로드한다.

> 현재는 먼저 설치할 필요 없다. [공개 코드 조사](../../archive/docs/repair-03-ad-observation-2026-10-06/PUBLIC_RESEARCH.md)를 기반으로 설계와 자동 검증을 먼저 진행하고, 실제 재생에서 남는 문제를 좁힐 때 이 도구를 사용한다.

## 사용 순서

1. Chrome 주소창에서 `chrome://extensions`를 열고 개발자 모드를 켠다.
2. **압축해제된 확장 프로그램을 로드합니다**를 누르고 다음 폴더를 선택한다. OTTSub 루트와 구분한다.

   `D:\PowerNeJa\PythonWorkspace\Project_Dev\OTTSub\tools\ad-observer`

3. Netflix 탭을 새로고침하고 ‘피지컬 100 멕시코 시즌 1’의 광고가 나오는 회차를 연다. 개발판/스토어판 OTTSub 두 개를 동시에 켜지 않는다. 어느 OTTSub를 켰는지 별도로 기록한다.
4. **플레이어 전체화면을 끈 창 모드**에서 우측 위 ‘OTTSub 광고 관찰’ 패널의 **기록 시작**을 누른다. 시작 전까지는 플레이어 조회나 기록이 없다.
5. 본편이 보이면 **본편 확인**, 광고로 바뀌면 **광고 시작**, 광고가 이어서 바뀌면 **다음 광고**, 본편이 돌아오면 **본편 복귀**를 누른다. 버튼은 관찰 시점 표시이며 실제 경계보다 사람 반응만큼 늦을 수 있다. 광고가 이미 시작됐어도 기록을 시작하고 광고 시작 표시를 남길 수 있다.
6. 본편 복귀 후 약 15–30초 더 재생하고 **JSON 저장**을 누른다. 기록을 멈추고 `ottsub-ad-observation-날짜.json`을 Chrome 다운로드 위치에 저장한다. 광고가 재현되지 않았어도 실제 결과 그대로 저장한다.
7. 파일 경로와 작품/시즌/회차, 사용한 OTTSub 경로(또는 스토어판)를 알려주면 로그를 분석한다. 기록 종료 뒤 임시 확장을 끄고 Netflix를 새로고침하면 패널도 제거된다.

계정 로그인은 평소 Chrome에서 직접 한다. 콘솔 코드 붙여넣기나 보안 경고 해제는 필요 없다. 패널이 안 보이면 도구가 활성화됐는지, 주소가 `https://www.netflix.com/`인지 확인한다.

기록은 페이지 메모리에만 있으므로 **새로고침/탭 닫기 전에 저장**한다. 최대 15분 또는 12,000행에서 자동 정지하고 저장을 기다린다. 재생 페이지를 벗어나도 정지한다. 정지된 기록은 다시 덮어쓰지 않으며 저장 후 ‘기록 비우기’로 다음 수집을 시작한다.

## 수집 범위와 한계

- 500ms마다 회차 숫자 ID, video의 시간/길이/재생 상태/배율 및 화면 노출 여부, 최대 8개의 player session을 기록한다. 세션·비디오·소스 URL은 각각 s1/v1/src1 같은 별칭으로 구분한다. URL 원문과 원래 세션 ID는 파일에 넣지 않는다.
- rVFC는 각 비디오에 하나씩 요청하고 응답을 받은 다음 표본 주기에 다시 요청한다. 프레임 mediaTime과 응답 시각을 기록한다. 모든 프레임 녹화가 아니며 일시정지/백그라운드에서는 값이 오래됐거나 없을 수 있다.
- player의 고정된 읽기 후보 `getMovieId/getCurrentTime/getDuration/isPaused`만 존재할 때 호출한다. Netflix 내부 API이므로 없음/예외를 정상적인 진단 결과로 기록한다. 시간 단위는 **unknown**으로 보존하며 임의로 초/밀리초를 확정하지 않는다.
- 광고/시간 관련 메서드 이름을 제한적으로 열거하지만 `getAdState` 같은 미확인 메서드를 호출하지 않는다. 실제 값 수집이 필요하면 확인 후 다음 진단에서 추가한다.
- `data-uia`와 일부 class에서 ad/advert 계열 이름을 가진 DOM 후보의 구조·표시 여부만 기록한다. 후보 발견은 광고 확정이 아니고, 후보가 없다고 광고가 없다는 뜻도 아니다. CSS 상속/가림 때문에 visible 추정이 실제 화면과 다를 수 있다.
- 본문/자막/제목/쿠키/저장소/응답 본문을 덤프하지 않는다. 프레임 이미지·오디오도 수집하지 않는다. 네트워크 전송 코드가 없으며 사용자가 누른 JSON 다운로드만 수행한다. 숫자 작품 ID, 시작 시각, UI 구조 이름은 기록에 포함된다.
- 페이지 MAIN world에서 실행되므로 페이지 코드와 환경을 공유한다. 로그는 관찰 보조 자료이며 변조 방지 기록이 아니다. 실제 Chrome에서 재생 성능 영향은 별도 확인해야 한다.
- OTTSub manifest 이벤트는 수신 가능한 경우 회차 숫자 ID만 기록한다. 이벤트가 없거나 누락돼도 Netflix manifest가 없다고 단정하지 않는다.
- 재생/탐색/언어 선택/자막 스타일은 변경하지 않는다. 패널은 재생 화면의 일부를 가릴 수 있으며 전체화면에서는 보이지 않을 수 있다.

## 로컬 요약

OTTSub 폴더에서 입력 파일과 새 출력 파일 경로를 지정한다. 기존 출력 파일은 덮어쓰지 않는다.

```powershell
node scripts/summarize-ad-observation.cjs "입력파일.json" "새요약파일.json"
```

PC에서 광고 표시 전후 표본, DOM 변화, 비디오 교체, 시간 표본 공백을 추린다. 이 요약기는 광고 감지기나 자동 싱크 보정기가 아니다. 실제 분석은 원본 로그의 연속 구간과 함께 수행한다.

## 검증

`node tests/test_ad_observer_browser.cjs`는 임시 Chromium에 이 확장을 실제 로드하고 Netflix 요청을 전부 모의 응답으로 처리한다. 자동 QA 실행기에도 포함된다. 실제 광고 관찰과 별개다.
